# FP&A の手引き

FP&A は、毎月の見込のサイクルを回し、シナリオとマスタを管理します。毎月の作業は、ホームの「**今月の作業**」に沿って進めれば漏れません。

## 月次のサイクル（今月の作業） {#cycle}

ホームの「今月の作業」は、データから自動で各ステップを「済み・今ここ・まだ」に判定します。「今ここ」のステップのリンクから作業します。

![ホーム（FP&A）: 今月の作業](/manual/fpa-work.png)

| ステップ | 作業 | 画面 |
| --- | --- | --- |
| ① 実績を取り込む | 会計の締めの後、その月の明細の CSV を取り込む | シナリオ管理の「実績を取り込む」 |
| ② 未割当をなくす | どの施策のものか分からない実績を、施策に割り当てる | 実績の割当 |
| ③ 月次の見込を始める | 前の版をロックして複製し、今回の見込を作る | シナリオ管理の「月次の見込を始める」 |
| ④ 締切を入れる | 現場の更新の締切日を入れる（担当者に通知が届く） | 月次の見込を始めるとき、またはシナリオの設定 |
| ⑤ 現場の更新 | 進み具合を見て、遅れている人に催促する | 今月の作業の「更新の状況」 |

すべて済むと、次の月の実績の取込を案内します。締めた後に実績が修正され、ロック済みのシナリオと食い違うときは、チェックリストの上に注意が出ます（[締めた後の実績の修正](#corrections)）。

### ① 実績を取り込む {#import}

1. 会計システムから、月の明細を CSV で出す（列: `target_month`, `account_code`, `department_code`, `box_code`, `amount`, `description`）
2. シナリオ管理の「実績を取り込む」でファイルを選び、「内容を確認」
3. 割当の根拠ごと（施策コード・外部コード・割当ルール・未割当）の件数と、月別の収益・費用の合計を、会計システムと突き合わせる
4. 変更理由（例: 2026-09 実績取込）を書いて「取り込む」

- CSV に含まれる月の明細は、その月の既存の明細と全部入れ替わります。修正があれば同じ月を取り込み直してください。
- 割当の順番: `box_code` が施策コード・外部コードに一致 → 割当ルール（会計科目 × 部門）→ どれもなければ未割当。
- 対象外の会計科目（アプリの科目が空）の行は取り込みません。未登録の会計科目があるとエラーになります。先に「会計科目」に登録してください。

### ② 未割当をなくす {#unallocated}

「実績の割当」の「未割当の実績を施策に割り当てる」で、まとまり（箱の ID ごと、または会計科目 × 部門ごと）に施策を選びます。

- 箱の ID があるまとまりは、その ID が施策の**外部コード**として登録され、次回から自動で割り当たります。
- 箱の ID がないまとまりは、**割当ルール**（会計科目 × 部門 → 施策）として登録されます。
- 共通費など、決まった施策に入らない費用は、受け皿の施策（コストプール型）を作って割り当てます。
- 割当を間違えたときや、ルールを変えたときは「再割当」で過去の月をまとめて割り当て直せます。

### ③ 月次の見込を始める {#start}

シナリオ管理の「月次の見込を始める」で、新しい版の名前（例: 2026年10月見込）、決算確定月（既定は取り込み済みの最後の月）、締切日を入れます。

実行すると、次をまとめて行います。

1. 今の版（今回の見込）をロックする（実績を固定する）
2. 今の版を複製して、新しい版を作る
3. 新しい版の決算確定月を設定し、計算式の金額を計算し直す
4. 「最新見込」を新しい版に付け替え、前回見込を今の版にする
5. 新しい版を今回の見込（作成中）にし、締切を入れる

確認画面で、変わる内容と注意（未取込の月・未割当・未完了の施策・実績の修正）を確かめます。注意があっても始められます。

### ④ 締切と通知 {#deadline}

締切を入れると、担当者に「見込の更新が始まりました」が届きます。その後は自動で、締切の前（既定は3日前と前日）と、締切を過ぎてから毎日、未完了の担当者に届きます（土日は送りません）。締切を過ぎると、ユニットのマネージャーにも未完了の一覧が届きます。

### ⑤ 現場の更新と催促 {#remind}

「更新の状況」で、全体・ユニット別の完了率と、未完了の担当者を確かめます。担当者の「**催促する**」で、その人の未完了の施策の一覧を、アプリ内のお知らせと Slack（メンション）で送ります。同じ人には1日1回までです。担当者がいない施策は「担当者なし」に出ます。施策の担当者を決めてください。

## 年度の始まりと終わり {#year}

### 期初計画を始める {#initial}

シナリオ管理の「新年度の期初計画を始める」で、新しい年度の**空の版**を作り、「期初計画」のエイリアスを付けて今回の見込にします。施策・内訳・ドライバーの定義は年度をまたいで残るので、現場は金額を入れるだけです。まとめて入れるときは、シナリオの画面の「計画値の CSV」を使います。

### 年度を締める {#close}

会計の決算が確定したら、シナリオ管理の「年度の締め」で年度を締めます。締めた年度の実績は取り込み直せず、再割当もできません。誤って締めたときは「締めを解除」できます（理由が必要です）。

### 締めた後の実績の修正 {#corrections}

ロック済みのシナリオは、ロックしたときの実績を保存しています。会計側で過去の月が修正され、取り込み直すと、取込の確認画面に「ロック済みのシナリオとの食い違い」が出ます。シナリオ管理の一覧で「実績の修正あり」のシナリオは、「実績を最新にする」で今の実績に入れ替えられます（ロックは外れません）。

## シナリオ管理 {#scenarios}

| 項目 | 説明 |
| --- | --- |
| エイリアス | 期初計画・修正計画・最新見込。年度ごとに1つずつ。「目標」は修正計画、なければ期初計画 |
| 決算確定月 | この月までは実績を表示する。進めると、担当者に「実績の反映」が届く |
| 前回見込 | 今回の見込と比べる版。月次の見込を始めると、自動で前の版になる |
| 作成中（今回の見込） | 現場が入力できる版。アプリ全体で1つ |
| ロック | 数字を固定する。解除には理由が必要 |

月次の見込を使わずに、シナリオを手で作る・複製する・設定を変えることもできます（シナリオの作成・シナリオの設定）。

## マスタと CSV {#masters}

メニューの「設定」（初めは閉じています）にあります。

- **組織・セグメント**: 集計の階層。ユニットは末端にだけ所属できます。
- **ユニット**: 種別（サービス・共通費・管理部門）、所属、マネージャー。施策がなくなったユニットは廃止、ユニットどうしは統合できます。
- **勘定科目**: P/L の科目。人件費など、金額から個人の情報が推測できる科目には「閲覧制限」を付けます（FP&A と経営陣だけが金額を見られ、入力は FP&A だけ）。
- **会計科目**: 会計システムの科目と、アプリの科目の対応。給与など、摘要に個人名が入る科目は「明細を FP&A 以外に見せない」にします。
- **割当ルール**: 会計科目 × 部門 → 施策。
- **確度の段階**: A〜E の名前・確率・判定基準。
- **ユーザー**: ロール、Slack のメンバー ID（メンション用）。無効にするときは、担当している施策の後任者を選びます。

各画面の「CSV エクスポート」「CSV インポート」でまとめて編集できます。インポートは追加と更新だけで、CSV にないデータは消えません。「内容を確認」で件数を確かめてから取り込みます。

## 組織変更の予約 {#orgchange}

「組織変更の予約」で、名前と有効日を付けて、施策の移動・ユニットの所属の変更・ユニットの統合・担当者の変更をまとめて登録します。有効日の 0:00 に自動で適用されます（「今すぐ適用」もできます）。過去の数字は、今の組織に組み替えて比べます。新しいユニットなどは、先にマスタで作っておきます。

## 通知の設定 {#notifications}

「通知の設定」で、通知の種類ごとの有効・無効、締切の何日前に知らせるか、送信時刻を変えられます。Slack は、サーバーの設定（Webhook の URL）が入っていれば送ります。「テスト送信」で確かめられます。「送信の記録」で、いつ何を送ったかと Slack の結果を見られます。

## 変更履歴 {#history}

すべての数字とマスタの変更は、変更理由と一緒に変更履歴に残ります。メニューの「変更履歴」で、シナリオ・施策・人・期間・理由の有無で絞り込めます。担当者・マネージャーは、自分が編集できる施策の履歴だけを、施策の画面から見られます。
