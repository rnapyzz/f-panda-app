# 研修・試用の環境（I-28）

現場に使い方を覚えてもらう研修や、新しい機能を試すための環境。本番とは別のデータ（デモのデータ）で動かすので、練習の変更履歴や通知が本番に残らない。

## 起動と片付け

```bash
make demo        # 起動（初回はデモのデータを入れる）。http://localhost:18100
make demo-reset  # デモのデータの初期の状態に戻す（研修の前に）
make demo-down   # 止めて、データも消す
```

- 開発環境（`make up`、8080）とは別のスタック（`fpanda-demo`、ポート 18100・DB 13308）で動く。開発環境と同時に起動できる。
- Slack には送らない（アプリ内のお知らせは届く）。
- 研修では、この PC の画面を共有するか、同じネットワークの PC から `http://<この PC のアドレス>:18100` を開く。

## 開発環境にデモのデータを入れる

開発中に、具体的なデータで画面を確かめたいときは、開発環境（`make up`、8080）をデモのデータで作り直せる。

```bash
make dev-demo          # 確認のあと、開発環境のデータをすべて消して、デモのデータを入れる
FORCE=1 make dev-demo  # 確認しない
```

- 消すのはこの PC の開発環境の Docker のボリューム（DB）だけ。開発環境で作ったアカウント・データ・計測用の DB（`make perf`）も消える。
- アカウントは下の表と同じ（FP&A は demo-admin@example.com）。
- 研修・試用の環境（18100）とは別。研修には `make demo` を使う。

## 別の環境に入れるとき

研修用にサーバーを用意したときや、本番（docs/deploy.md）をデモとして使うときは、FP&A のアカウントを作ってから、デモのデータだけを入れられる。

インターネットに公開している環境では、**デモのアカウント（佐藤・鈴木・田中・山田）のパスワードを `DEMO_MEMBER_PASSWORD` で必ず指定する**。既定の `demo-member-password` はリポジトリで公開されているため、だれでもログインできてしまう。パスワードは画面に出さずに入力する（Mac の既定の zsh の書き方。bash では `read -rs -p "<表示する文>" <変数名>`）:

```bash
read -rs "DEMO_ADMIN_PASSWORD?FP&A のパスワード: "; echo
read -rs "DEMO_MEMBER_PASSWORD?デモのアカウントのパスワード（12文字以上）: "; echo
export DEMO_ADMIN_PASSWORD DEMO_MEMBER_PASSWORD
DEMO_URL=https://training.example.com DEMO_ADMIN_EMAIL=you@example.com scripts/demo.sh seed
```

ログインに失敗したとき（「メールアドレスまたはパスワードが正しくありません」）は、ブラウザーで同じメールアドレス・パスワードでログインできるかを確かめる。15 分間に 5 回失敗すると、15 分間ログインできなくなる。

### あとから増えたデモのデータを足す

デモのデータを入れた後に増えた部分（取引先。docs/plan.md「2.29」）は、`scripts/demo.sh partners` で足せる。施策がある環境でも動き、何度実行しても同じ結果になる（同じ取引先は取引先名・会社名・区分で探し、内訳に取引先が付いていなければ付ける）。デモの施策がない環境では、取引先だけを入れる。

```bash
read -rs "DEMO_ADMIN_PASSWORD?FP&A のパスワード: "; echo
export DEMO_ADMIN_PASSWORD
DEMO_URL=https://training.example.com DEMO_ADMIN_EMAIL=you@example.com scripts/demo.sh partners
```

シナリオの説明（docs/plan.md「2.31」）は、`scripts/demo.sh narratives` で足せる（同じく `DEMO_URL` などを付けて実行する）。デモのシナリオ（「2026年度 期初計画」「2026年度 10月見込」）のうち、説明がまだなく、ロックされていないものにだけ入れる。何度実行しても同じ結果になる。

- 施策が1件でもある環境には入れない（本番に誤って入れないため）。
- SSO（Google）を有効にした環境では、パスワードでログインできるのは FP&A だけ（docs/architecture.md「認証」）。デモのアカウント（example.com）で現場の練習をするときは、SSO を設定しない研修用の環境にする。
