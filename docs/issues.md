# 運用上の課題（俯瞰チェック）

このアプリで経営管理・FP&A を運用するときに想定される課題をまとめる。機能の追加とは別に、定期的にアプリ全体を見直して（俯瞰チェック）、このファイルを更新する。

- 課題には ID（`I-<連番>`）を振り、解決しても ID は使い回さない。
- 状態は **未着手**／**検討中**／**対応済み**／**見送り**。対応済み・見送りは、対応した PR や理由を書く。
- 仕様が決まったら `docs/plan.md` に反映し、ここには要点とリンクだけを残す。

## 課題一覧

優先度は **高**（運用が成り立たない・数字の信頼を失う）／**中**（運用の負担が大きい）／**低**（規模や将来の要件しだい）。

### 1. 数字の土台：会計の数字と合わない

| ID | 優先度 | 課題 | 対応の方向 | 状態 |
| -- | ------ | ---- | ---------- | ---- |
| I-01 | 高 | **実績を施策に割り当てるルールがない。** 会計の実績は「勘定科目 × 部門」で締まり、施策単位にはなっていない。今は FP&A がアプリの外で CSV を施策コード・外部コードに加工しており（6.1）、毎月の締めの手作業になる | 会計の明細を取り込み、箱の ID → 割当ルール → 未割当 の順に割り当てる（docs/plan.md「2.12」） | 対応済み（仕様 #45、実装 #46） |
| I-02 | 高 | **施策の合計と全社の P/L が合わない。** 施策に紐づかない数字（既存事業の自然体、共通費、本社費、人件費、決算整理）があると、施策の合計が全社の P/L とずれる。漏れていても気づけない | 未割当も実績として取り込み、アプリの合計を会計と常に一致させる。共通費は受け皿の施策で受ける（docs/plan.md「2.12」） | 対応済み（仕様 #45、実装 #46） |
| I-03 | 中 | **締めた後の実績の修正。** ロック時に実績を固定するため、後から会計側で修正（遡及修正）が入るとアプリと会計がずれる | 正は会計。食い違いを取込の確認とシナリオ管理で知らせ、FP&A がロック済みのシナリオの実績を最新にできる。年度を締めて取り込み直しを止める（docs/plan.md「2.14」） | 対応済み（仕様 #49、実装 #50） |

### 2. 入力の質：数字が正直に入らない

### 3. 運用サイクル：人が動かない

| ID | 優先度 | 課題 | 対応の方向 | 状態 |
| -- | ------ | ---- | ---------- | ---- |
| I-07 | 高 | **締切と通知がない。** メール・Slack の通知も締切日もなく、現場はアプリを開かないと気づかない。FP&A が個別に催促することになる | 作成中のシナリオに締切を1つ持たせ、更新の開始・締切の前・締切の超過・実績の反映を、アプリ内のお知らせと Slack で自動で送る（docs/plan.md「2.13」） | 対応済み（仕様 #47、実装 #48） |

| I-09 | 中 | **組織変更・異動に弱い。** 期中にユニットが変わる・担当者が異動すると、過去シナリオとの比較や「所管ユニット」の範囲が崩れる | 過去も今の組織で集計（組替え）。組織変更の予約（有効日に自動で適用）、ユニットの統合、無効化のときの後任者（docs/plan.md「2.15」） | 対応済み（仕様 #51、実装 #52） |

## 対応の記録

### 実績の割当（I-01・I-02）

- 会計の数字を「外から入る数字（ID の付いた箱がある）」と「会計システムに直接入る数字（箱がない）」に分けて整理した（2026-10-06）。
- 仕様は docs/plan.md「2.12 実績の割当」。箱の ID は外部コードで、箱のない数字は割当ルール（会計科目 × 部門）で受け皿の施策に割り当てる。どちらにも当たらない行は未割当として取り込み、FP&A が一覧で施策を選ぶ（選んだ結果はルールとして残る）。
- 残る論点: 締めた後の会計側の修正（I-03）、人件費の扱い（I-11）
